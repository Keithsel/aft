# AFT agent-text habit audit — 2026-07

**Scope:** Report-only audit of AFT's agent-facing result text, wake/nudge text, plugin-injected workflow hints, tool descriptions, committed subc schemas, and permission/steering messages against the six ALF fleet habit-training defect classes.

**Base:** `ba0e539bc7b4c8225304434d624e1acf485a1b94` (current main HEAD at audit time)

**Decision rule:** A finding is a string that can teach a generalized agent habit that is wrong, unbounded, or completion-unsafe. A PASS means the surface was inspected and adjudicated as safe for the stated reason; it does not mean the surface was skipped.

## Coverage and method

Inspected the complete formatter set in `crates/aft/src/subc_format.rs`, response finalization, the bash orchestration/status/watch paths and background registry, inspect/search/callgraph/edit/mutation result paths, both plugin notification and workflow-hint implementations, the agent-facing tool factories in both hosts, the committed `crates/aft/src/subc_tool_schemas.json`, and permission/sandbox steering strings. Searches covered stop/wake language, automatic-delivery claims, absolute language, retry/check-again wording, partial/completion markers, distinctive tags and headers, stale/pending wording, and no-re-read claims.

Tests, fixtures, release notes, and historical capture files were not counted as runtime findings. Documentation was read where it establishes the delivery mechanism or the documented result contract. The PASS section records the inspected surfaces that produced no finding.

## PASS — inspected and adjudicated correct

The following were explicitly inspected and are not omitted findings:

- **Default background completion/reminder path — PASS for A/F.** The launch, foreground-promotion, and running-status strings (`crates/aft/src/commands/bash_orchestrate.rs:55-93, 597-617`; `packages/opencode-plugin/src/tools/bash.ts:517`; `packages/pi-plugin/src/tools/bash.ts:758-793, 1277`; and both workflow-hint blocks) have a real delivery path. The Rust registry persists background tasks and undelivered completions; `completion_delivered` is acknowledged only after plugin append/wake delivery; `replay_session` rehydrates tasks after a bridge restart; and the plugin drains on the next foreground tool result/session-idle path (with a dedicated subc `bg_events` wake path). The documented boundary is “when the task exits,” with replay on the next bridge/session drain—not a free-standing promise after an agent simply stops. This PASS is for default completion reminders, not the non-persistent explicit pattern watch in finding 5.
- **Foreground promotion wording — PASS for A/F after the mechanism check.** `Foreground bash didn't finish within ... and was promoted to background: ... A completion reminder will be delivered automatically; use bash_status ...` names a real task ID and the next actions. The task is persisted, and the bridge explicitly rehydrates undelivered completions after a killed/restarted binary. The same string is therefore a qualified wake-backed handoff, not announce-then-stop with no owner.
- **`bash_status` anti-polling descriptions — PASS for B/C.** `packages/opencode-plugin/src/tools/bash.ts:421-425` and `packages/pi-plugin/src/tools/bash.ts:621-627` say the tool is a read-only snapshot that returns immediately, then name `bash_watch` for waiting. That is an operating-condition statement about the tool's API, and the one-shot wording is paired with a real wait/notification alternative. It is not an instruction to spin on status.
- **`bash_watch` sync/async boundary — PASS for A.** The descriptions at `packages/opencode-plugin/src/tools/bash_watch.ts:55-59` and `packages/pi-plugin/src/tools/bash.ts:650-655` distinguish blocking sync mode from non-blocking async mode, state that a user interruption converts sync waiting to an async watch, and name the “parallel work or end your turn” use case. The sync abort result explicitly registers the equivalent async watch. The missing restart boundary for that watch itself is the separate finding above.
- **Subagent end-of-turn warning — PASS for A.** `packages/opencode-plugin/src/tools/bash.ts:550-554` says: `Continue with other work if you have it. If you don't, call bash_watch(...) to wait for completion before returning to the parent. Subagents don't survive turn-end and won't receive the completion reminder.` It names the real boundary and tells the subagent to wait before returning; it does not generalize a primary-session wake to a subagent.
- **`wait:true` direct description — PASS for its own scope.** `packages/opencode-plugin/src/tools/bash.ts:242-247`, `packages/pi-plugin/src/tools/bash.ts:114-118`, and the corresponding schema text explicitly say no auto-promotion and that a new user message detaches the wait. The timeout-parameter sentence still needs the condition proposed in finding 7, but the dedicated `wait` argument description itself is correctly bounded.
- **Partial-result and dry-run text — PASS for D.** `format_ast_search`, `format_ast_replace`, outline, zoom, search, and edit paths retain explicit `partial/incomplete`, skipped-file, dry-run, capped, lower-bound, rollback, or no-net-change signals (`crates/aft/src/subc_format.rs:913-920, 1278-1321, 1342-1364, 1488-1492, 1591-1641, 1724-1729, 1782-1787, 2425-2445`). They do not turn previews or incomplete transactions into completed mutations. The move source-delete branch is the named exception because its partial warning is dropped by `format_move`.
- **Search honesty and rerun guidance — PASS for C/D/E.** The grep cap says `if you hit the cap, narrow with path or include and re-run` (`packages/opencode-plugin/src/tools/search.ts:151-155`, committed schema `:235`), and the result footer says `(capped)` or `[index: fallback]` when relevant (`crates/aft/src/commands/grep.rs:195-222`). `aft_search` adds `more results available`, `enumeration capped`, `fully degraded`, and `partial/incomplete` notes (`crates/aft/src/subc_format.rs:1529-1562`). The trigger is the explicit cap/degraded state and the retry changes scope; these are bounded disclosures, not polling or reply templates.
- **Search routing disclosures and grep nudge — PASS for E.** `[interpreted_as: literal|regex]` (`crates/aft/src/commands/semantic_search.rs:2718-2725`), `[index: fallback]`, and `DO NOT search code by running grep/rg in bash ... Use the aft_search/grep tool instead` (`crates/aft/src/bash_rewrite/footer.rs:14-28`) are provenance/action metadata. They do not contain a question, sign-off, response heading, or imitation template. The same applies to the workflow-hint “DO NOT use bash for code search” footer.
- **Inspect's honest incomplete contract — PASS for D, with finding 4 covering the missing trigger.** Tool descriptions say Tier 2 returns `complete: false` and `pending_categories` rather than fabricated clean counts (`packages/opencode-plugin/src/tools/inspect.ts:111-117`, `packages/pi-plugin/src/tools/inspect.ts:376-384`, `crates/aft/src/subc_tool_schemas.json:443`). The result renderer reports “so far,” “incomplete,” or “pending” and preserves server names (`crates/aft/src/subc_format.rs:1931-1999`, `packages/pi-plugin/src/tools/inspect.ts:111-140`). This is honest state reporting; only the follow-up trigger wording is a finding.
- **Freshness-aware edit/read guidance — PASS where it is conditional.** Extensive formatter reflow says `re-read the file before your next anchored edit` (`crates/aft/src/subc_format.rs:1087-1095`); a partial patch says the patch may have been partially applied and to re-read before retry (`crates/aft/src/patch/apply.rs:232-242`); and the missing-source move error says to verify with `read` before retrying (`crates/aft/src/commands/move_file.rs:55-67`). Each names the state that invalidates the next action. Finding 1 is the opposite, unconditional no-re-read claim.
- **Permission/sandbox steering — PASS for A/D.** External-path denials say the path is blocked, whether per-call override is possible, and which config change is required (`packages/opencode-plugin/src/tools/permissions.ts:56-62`). Host escalation text names the exact command, working directory, interactive approval boundary, and denial (`packages/opencode-plugin/src/tools/bash.ts:134-136, 158-171`; `packages/pi-plugin/src/tools/bash.ts:318-373`). Sandbox-unavailable status says the command did not run and names the config dependency (`crates/aft/src/commands/bash_status.rs:74-87`). These messages do not model an unperformed action as complete and do not invite blind retries.

## Top five highest-yield fixes

1. Add an invalidation condition to the rank-0 `aft_search` no-re-read notice (finding 1); it directly shapes edit behavior across every language.
2. Persist explicit pattern watches or state their bridge/session lifetime and re-registration rule (finding 5); this removes the only end-turn promise found without a replayed wake.
3. Replace stale/pending inspect wording with the actual idle/inspect-triggered refresh boundary and an explicit no-poll instruction (finding 4).
4. Render the move source-delete failure as partial rather than “Moved” (finding 2); this protects filesystem state and completion accounting in the failure branch.
5. Bound the LSP pending and bridge-busy follow-ups to a later normal observation/completion wake (findings 3 and 6); this removes two independent routes into status polling.
